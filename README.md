### 6.3 项目三：控制台多人聊天室

#### 业务与结构

使用Java Socket开发控制台即时通讯系统，包含服务端与客户端两个模块，实现多用户同时在线、消息广播和上下线通知。

#### 服务端功能

- 绑定固定端口（例如8888），持续监听连接请求。
- 每个客户端由独立子线程处理，维护昵称与通信输出通道组成的全局在线用户列表。
- 注册时校验昵称唯一性，重复则提示重新输入，成功后才能进入在线列表及聊天流程。
- 收到普通消息后向除发送者外的所有在线用户广播，格式为 `[昵称] 消息内容`。
- 上线广播为 `【系统】欢迎 昵称 加入聊天室！`；主动退出或异常断开时广播 `【系统】昵称 已退出聊天室。`。
- 单个客户端异常不影响整体服务；离线后及时清理用户数据、关闭连接并结束对应处理线程。

#### 客户端功能

- 支持输入服务端IP和端口，并提供默认配置。
- 连接后先完成昵称注册，重复时可重新输入，成功后进入聊天界面。
- 支持文本消息发送，拦截空消息；使用 `/quit` 主动退出。
- 使用独立子线程持续接收消息，保证输入与接收可同时进行，输出清楚可辨。
- 主动退出或断开连接后给出提示，关闭Socket并释放资源、安全结束线程。

#### 协议与日志

采用按行分隔的纯文本协议：

| 消息类型 | 格式 |
| --- | --- |
| 昵称提交 | `NICK:昵称` |
| 注册通过 | `OK` |
| 昵称重复 | `ERROR_NICK` |
| 普通消息 | 直接传输文本内容 |
| 用户消息广播 | `【昵称】消息` |
| 系统广播 | `【系统】xxx` |

服务端须记录运行日志和聊天消息日志。面对网络异常、强制断开等情况，向用户提供友好提示，不直接展示底层异常栈，可将异常详情写入日志。多人同时在线时应保证用户列表与消息发送的并发安全，不因单用户异常导致服务宕机。

# 整体步骤&流程
1. OnlineUserManager.java（server 包）
先写在线用户集合 + 加锁的 addUser / removeUser / broadcast。

2. ServerLogger.java（server 包）
日志工具，logRun / logChat，先保证能往 logs/ 写文件。

3. ChatServer.java（server 包）
只写 ServerSocket 绑定 8888 + accept() 循环，先把"能接连接"跑通，还不处理消息。

4. ClientHandler.java（server 包）
先写昵称注册协议：收 NICK:xxx → 校验 → 回 OK / ERROR_NICK；调通注册后，再加消息广播循环、finally 里的下线清理。

5. ChatClient.java（client 包）
先写连接 + 注册流程，能成功进聊天室再说。

6. ReceiveMsgThread.java（client 包）
最后加接收子线程，解决"输入时收不到消息"的问题；再补 /quit、空消息拦截。
